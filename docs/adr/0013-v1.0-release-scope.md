# 0013. v1.0 release scope

- Status: Accepted (amended by 0018)
- Date: 2026-10-05
- Requirements: all
- Amends: 0010 (phase order), 0012 (timing of the read-only credential check)

## Context

After phase 0, the product owner set the goal for the first release: a clean,
professional v1.0 that syncs all instance data and offers the core actions, with
enforced code quality and performance. The phase order in ADR-0010 put governance before
push and knowledge; v1.0 needs a narrower, operational first release.

## Decision

v1.0 delivers (plan: `specs/002-v1.0-release/plan.md`):

- workspaces (ADR-0014), instance profiles and credentials;
- `doctor`, including instance checks;
- full and incremental `pull` of all `sys_metadata` classes, child rows, operational
  inventory and update sets; `integrate`; `status`;
- update sets: list, show, collisions, export as XML;
- plugins: list, and activate through the CI/CD API, **on development instances only**.

Product owner decisions (2026-10-05), following the plan's recommendations:

1. **Plan and push move to v1.1**, together with governance rules, `check`, `validate`,
   agent packs and host hooks. Push is not shipped without its gate.
2. **Test and production profiles are allowed for `pull` only.** Write use cases are not
   registered for those kinds (ADR-0012, layer 3). Until spike S6 proves the credential
   itself is read-only, `instance add` for those kinds requires an explicit
   acknowledgement that read-only access is the user's responsibility.
3. **YAML writing style:** the project's own style (ADR-0015).

Later releases: v1.1 push and governance; v1.2 knowledge and audit; v1.3 remote
update-set validation and promotion guard; production troubleshooting after that.

## Consequences

- v1.0 never writes metadata to ServiceNow. Its only write is plugin activation on a
  development instance.
- Spike S6 must be done before the read-only credential check (ADR-0012, layer 4) can
  ship, at the latest with production troubleshooting.
- Still open before milestone M8: code signing (Apple notarization, Windows signing).
