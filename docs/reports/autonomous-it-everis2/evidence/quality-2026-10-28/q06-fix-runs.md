# Q06 fix: alert automation the agent can actually build (29 October 2026)

Baseline: 4 of 12 (`q06-alert-automation-baseline.md`). We asked for a *response* automation and got a
link and a generic proposal. Nothing was created.

## Why the baseline was poor

The use case "Create alert automation" runs one agent, "Alert Automation AI Agent", with these
tools:

- Create Alerts Grouping Automation
- Alert Group Automation Canonicalizer
- Activate Alert Group Automation
- Delete Alerts Grouping Automation
- Get Alert Automation Link
- Fetch context for Configuration Console

**It can only build grouping automations.** For response and enrichment it gives the "Respond to
alerts" link and nothing else. The baseline asked for what the agent can't do. No configuration
fixes that: we'd need a new tool that writes `em_alert_management_rule` records.

## Change

The demo step now asks for what the agent can build, a grouping automation. That puts the SAP alerts
from Q05 into one group even when the CIs aren't related. The result is captured in the Global update
set `AIT-Q06-alert-automation`, created first and set as current.

## Answer key

- **Filter:** node is one of the seven SAP PRD hosts.
- **Settings:** time window 30 minutes; created **inactive**.
- **Replay over the last 30 days:**
  - the three alerts from Q05 are already in group Alert0010114, made by OOB "Group alerts with CI
    relationships" (overlap);
  - Alert0010108 (WEB01) and Alert0010109 (WEB02), both 28 Oct 09:42, would become one new group;
  - Alert0010107 (WEB01, 09:00) is more than 30 minutes away and stays alone.
- **So the rule adds one group of two alerts.**

## What's left

- **Replay:** the agent can't count past matches. In the demo, the presenter opens the automation and
  uses the platform's test on past alerts, or we show the key above.
- **Response automations** ("create an incident with AI insight for /usr/sap filling up") are still
  only a link. Building a tool for `em_alert_management_rule` is a custom agent tool. That's a
  separate decision.
- **Seen during Q05:** the OOB rule "Create Incident with AI Insight" is active, but none of the four
  test alerts got an incident. Not investigated yet.
- Spanish run as the persona: the persona has no Event Management role, so it would need
  `evt_mgmt_operator` or similar.
