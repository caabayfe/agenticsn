# v1.0 performance targets (plan section 4.4)

All runs against the PDI (dev312411, Europe to US, about 0.6 s per request). M8 requires each
target to be met or explicitly accepted by the product owner.

**Accepted by the product owner on 2026-10-06** as they stand, including the full-pull
baseline (no v1 measurement to compare with) and the revised idle-pull target.

| Measure | Target | Result | Status |
|---|---|---|---|
| Full pull of the PDI | Baseline in M3, then ≤ v1's time | 463,316 records in 29 min, 5,180 requests, 0 retries ([baseline](pull-baseline-pdi.md)) | **Needs acceptance**: v1's full-pull time was never measured, and v1 mirrored only 280,000 records (it excluded derived and child data that v1.0 keeps) |
| Incremental pull, nothing changed | ≤ 5 requests and < 10 s (ASR-16) | 22 requests, 4.4 s, 3.2 s of server time | **Met as revised**: ASR-16 was revised after M4 measurements to one aggregate per change source (20) plus the inventory's 2 signals; the original 5 could not see layout or flow changes (ADR-0016) |
| Incremental pull, 100 changed records | < 60 s | 110 changed records: 13.7 s, 66 requests, 12.8 s of server time | Met |
| Peak memory during a full pull | < 1 GB | Physical footprint 457 MB; sampled resident size 1,048 MB | **Met for the footprint**; the resident size includes memory the runtime reserved but did not return |
| Requests per changed record (incremental) | ≤ 2 amortized | 0.6 (66 requests for 110 records, including the 22 fixed ones) | Met |
| Domain diff of a 250k-record inventory | < 2 s | Not applicable: plan and push, which diff the inventory, moved to v1.1 (ADR-0013) | **Moves to v1.1** |

Other measured costs: `pull --verify` steady state 59 requests, 33 s, 15.9 s of server time
(its first run per workspace learns which rows are hidden from the user: 987 requests, 7.4 min);
`status` 3.1 s on 620,000 files, no requests; `integrate` after an incremental pull 1.4 s.
